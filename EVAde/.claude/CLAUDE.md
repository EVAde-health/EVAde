# CLAUDE

Project-specific guidance for AI coding agents.

## EVAde project conventions (follow these on every change)

EVAde is an astronaut health-monitoring web app (NASA Space Apps 2026). Vite + React 19 + TypeScript,
Astryx UI, React Router 7, Recharts. All data comes from the `evade-api` Cloudflare Worker (`cloud/worker`,
D1 `evade-db`); there is no mock data. Sign-in is Cloudflare Access (`/auth/access`, listed by `/auth/providers`) with an HttpOnly
session cookie — the browser never holds a token or key. Never put secrets in `VITE_*` variables.
New users have no readings: every panel must render `NoReadings` instead of inventing values.

### File structure
```
src/
  App.tsx            Root: Theme, BrowserRouter, LinkProvider, every route (AppFrame gates signed-in routes).
                     Import every page here (React.lazy) — App.tsx is where the app is assembled.
  main.tsx           Mounts <App/>, imports global CSS + fonts only. No App.css — never create one.
  index.css          Global styles only (body, view transitions, shared animations/utilities).
  pages/             One file per route: LandingPage, LoginPage, DashboardPage, TutorialsPage,
                     TasksPage, JournalPage, SelfiesPage, ResearchPage.
  pages/css/         <PageName>.css — styles for exactly that page (e.g. pages/css/DashboardPage.css).
  components/        Reusable components (panels, tiles, charts, shell, hero pieces).
  components/css/    <ComponentName>.css — styles for exactly that component.
  assets/            Images/SVGs used by the web app (logo, ISS, etc.).
  context/           React contexts + hooks (MissionContext = user/XP/tasks/meals, HealthDataContext =
                     metrics/readings/alerts/radiation for the dashboard, ColorModeContext).
  hooks/             Custom hooks (useColorMode, usePersistentState, useCamera, useCountUp …).
  data/              Pure domain helpers over API rows (metrics, health, tasks, tutorials, status). No mock data.
                     Exception: research.ts + research/ hold published NASA reference values, each with its
                     source and evidence label. They describe study crews, never the user's readings.
  services/          External I/O. api.ts = the only fetch (credentials, fixed origin); healthApi.ts =
                     typed endpoint calls; foodSearch / selfieStore (R2 /media) / journalAssistant wrap them.
                     XP is decided by the Worker — the UI only displays `points_awarded`.
  utils/             Tiny pure helpers.
  themes/            GENERATED by the Astryx theme editor — never hand-edit.
```
Routes change the URL via React Router (`/`, `/login`, `/dashboard`, `/tutorials`, `/tasks`,
`/journal`, `/selfies`, `/research`). Astryx links route through `components/RouterLink.tsx` (View Transitions on).

### Code shape (every .tsx file)
1. Imports → module constants/types → helper functions → the functional component (default export).
2. Inside a component: all React hooks first, then derived values, then inner functions, then `return`.
3. Every function gets a one-line `//` summary of ~10 words above it. No long comment blocks.
4. Clear, descriptive names over comments.

### Design rules
- Color coding: health status is always `nominal | caution | critical` (`data/status.ts`) →
  success / warning / error tokens, always paired with an icon or label (`StatusBadge`, `StatusDot`).
- Charts: series colors from `components/chartConfig.ts` (validated categorical order:
  blue → orange → teal → purple). Never reuse status colors for series. No dual-axis charts.
  Every chart has a tooltip (`ChartTooltip`) and a legend when it has ≥ 2 series.
- Dynamic charts: offer several views of the same data (see `MetricExplorer`: Trend/Range/Zones/Rhythm/Table).
- Gamification: actions award XP through `useMission()` (toggleTask, addWater, addMeal, completeTutorial)
  and confirm with a toast.
- Light + dark mode: use tokens only, never mode-specific hex. Toggle lives in `ThemeToggle`.
- Motion: animate generously (entrances, hovers, pop-ups) with CSS/compositor properties; pause rAF loops when hidden.
  Reduced motion is an in-app preference (`MotionToggle` → `useReducedMotion`/`setReducedMotion`, `<html data-motion>`),
  not the OS flag. Gate heavy motion with `:root[data-motion='reduced']` in CSS or `useReducedMotion()` in TS.
- Scroll effects: `useScrollProgress` writes `--progress` (0–1) on an element; drive parallax from it in CSS.
- Glass: app pages sit on `AmbientBackdrop`; use `.glass` for frosted surfaces. Dialogs/popovers animate globally in index.css.
- Decorative elements (swatches, keys, glows, duplicated marquee items) get `aria-hidden="true"`.
- Performance: pages are lazy-loaded; keep Recharts imports inside dashboard components only.

CLI: run every command as `npx astryx <cmd>` (shown below as `astryx ...`).

SETUP (once, in app entry e.g. main.tsx) — without these, components render unstyled:
  import "@astryxdesign/core/reset.css";
  import "@astryxdesign/core/astryx.css";

WORKFLOW — start every page from a template, never from scratch:
1. `astryx build "<idea>"` — names the template to scaffold from and the parts it lacks.
2. `astryx template <name> <path>` — scaffold it; keep its frame, gap and padding; replace the content.
3. `astryx template <Block>` for parts it lacks; `astryx component <Name>` to read props before using one.
Changing an existing page? Keep it: skip step 2 and add blocks/components inside its sections.
Before you deliver a build, run `astryx doctor --built <dir>`; don't deliver it if it fails.

RULES:
- No <div> — components handle all layout and spacing.
- Read `astryx docs layout` before changing a template's frame.
- Dense data = rows (Table, List/Item), not Card-wrapped lists. Badge = counts only.
- Style with component props first, then tokens (var(--color-*|--spacing-*|--radius-*)). No raw hex/px. No StyleX/Tailwind compiler here — don't use xstyle/utility classes directly. Some templates use StyleX and need a compiler plugin; see `astryx docs styling-overview`.
- THEMES: palettes and custom colors go through the theme, never :root overrides. To make or change a theme (colors, fonts, corners, spacing, a look from a picture), prefer the experimental theme editor over hand-written theme files: `astryx experimental theme editor new <name> --like neutral`, then `editor set <name> <thing> <value>` or `editor how "<what you want>"`; wire it with `astryx theme add <name>`; after each change look at it with `astryx experimental theme editor show <name> --png` and open the PNGs it writes (changes nothing in the app); a theme change is not done until you have looked at the pictures. In code, extend an imported theme to customize it; `theme eject <slug>` only forks source. See `astryx docs theme`.
- SELF-CHECK: re-read the file; replace any raw <div>/<span>, imported .css/@apply, or hardcoded #hex/px with the component or a token.

`astryx help` lists every command. Key ones beyond the workflow:
  search "<query>"   find any component / hook / doc / template
  discover <words>   integrations you could add
  docs <topic>       getting-started, principles, tokens, theme … (`astryx docs` lists all)
  docs cli           commands and API reference
  docs authoring     build an integration package, and every field it holds
  upgrade --from <old version> --apply   run after a dependency bump
